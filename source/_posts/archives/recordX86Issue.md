# 前情提要:
{% note blue %}
<aside>
💡 `istoreOS`在线升级（保存配置）之后，qbt上传速度非常慢，查看`upnp`发现端口没有转发了。
问题在于手欠在线升级了OS版本，并且使用了保存配置。老的配置并不能适配所有版本。虽然能升级成功，但是会出现各种各样的问题。
然后我就选择了手动升级固件（并且不保存配置）的操作。结果是变砖了。
如何发现的呢？我网线连接X86软路由，发现我的电脑的IP被分配到了`168.254.X.X` 这明显是不正确的。
因为istoreOS的默认LAN IP是`192.168.100.1` , 我的电脑正确应该是被分配到 `192.168.100.x` ，但是没有。我知道我G了。
为了能看软路由的情况，中间还去借了键盘和鼠标。（mac触摸板害死人）

# 解决方案:

1. 搜索&下载 `Rufus`
2. 刷入 `istore_xxxx.img.gz` 固件
3. U盘插入软路由，BIOS设置U盘启动。

```bash
fdisk /dev/sda
g # g=generate，创建一个新的分区
w # w=write 写入
fdisk /dev/sda
n # new 创建一个新的子分区（默认即可）
w # w=write 写入
fdisk -l /dev/sda #用来查看，你的，g，n，这两个创建分区的结果是否有效。
```

1. 通过`网线`将`设备` 与`软路由LAN口` 连接。
2. 使用浏览器打开 `192.168.100.1`
3. 默认账号 `root` 默认密码 `password`
4. 从左边栏选择`文件传输`
5. 选择 `istore_xxxx_efi.img.gz` 固件上传

<aside>
💡 上传完成之后，会在下方显示**红色**的提示，提示内，有在ttyd中需要用到命令里的路径。

</aside>

1. 打开`ttyd终端` 登录

```bash
dd if=/tmp/upload/istor_xxxx_efi.img.gz of=/dev/sda
```

1. 等待几分钟后,会出现 `xxx in` , `xxx out` 的输出,一共两行，出现之后,输入`reboot`.

<aside>
💡 根据指示灯来判断**是否**开机,**拔出**U盘

</aside>

# Final

成功由`SSD`**启动**了`istore OS`，救砖**成功**

之后将`路由器`连接到`设备`，保持**断网**，只连接`LAN口`，然后打开设备上的浏览器，登录`192.168.100.1`

# 总结

`openwrt`系统不仅可以运行在硬盘中，还可以运行在别的地方，比如**U盘/移动硬盘/SD卡**。
由于硬盘**损坏**后，导致**无法引导启动**，于是通过将`openwrt`运行在`U盘`中的方式，进入系统。
并借助终端命令，重新设置硬盘。
由于这个时候`openwrt`已经运行在`U盘`中，那么只要打开`后台管理`界面，通过“`传输文件`”将`.img.gz`的文件上传到`路由器`的硬盘里进行刷机就可以了。
